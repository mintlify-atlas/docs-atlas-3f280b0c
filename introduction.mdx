ZPan is a lightweight file hosting platform built on top of S3-compatible storage. Files upload directly from the client to S3 through presigned URLs, bypassing server bandwidth entirely. The server is the control plane: auth, metadata, shares, quotas, teams, WebDAV, tool integrations, and admin operations. You bring an S3-compatible bucket; ZPan gives it a clean web UI, public sharing, image-hosting APIs, and deployment options that do not require a VPS or NAS.

## Core Scenarios

ZPan is purpose-built around S3-backed file workflows. It is not a wrapper around every consumer cloud drive and not a full groupware suite.

- **S3 web drive** — Manage files, folders, previews, trash, quotas, and team workspaces on top of your own object storage.
- **Image hosting** — Upload via PicGo, PicList, uPic, ShareX, Flameshot, or API and get a stable URL instantly.
- **File sharing** — Publish share links with password, expiration, download limits, direct links, and save-to-drive flows.
- **Personal homepage** — Give each user a public `/u/username` page for public shared files and folder-style browsing.
- **External access** — Mount files through WebDAV and run downloader workers for remote-download workflows.

## Why ZPan?

**S3 only, by design.** ZPan does not chase every net-disk provider or build a cloud-drive nesting layer. The storage contract stays simple and durable: S3-compatible buckets such as Cloudflare R2, AWS S3, Backblaze B2, MinIO, RustFS, Tigris, and other S3-compatible services.

**Cloudflare Workers first.** ZPan is built around Cloudflare Workers, D1, Hono, and web-standard APIs, with Docker and other runtimes as additional deployment targets. You can run a real file-hosting control plane without owning a VPS, keeping a NAS online, or proxying uploads through a long-running server.

**Direct transfer path.** Uploads and downloads use presigned object-storage URLs whenever possible. That keeps server bandwidth low, avoids a central file-transfer bottleneck, and lets object storage do the heavy lifting.

**Practical file workflows.** ZPan includes a web file manager, public sharing, image-hosting configuration, API keys, WebDAV access, teams, quotas, remote-download tasks, file previews, and admin controls without turning into a provider-aggregation platform.

**Deployable downloader workers.** Remote download does not have to run inside the main ZPan instance. You can deploy the downloader together with ZPan for a simple setup, or run it separately in an environment with better network access and fewer source-site restrictions, then let ZPan import the completed files into object storage.

## Architecture Overview

ZPan is a single-package full-stack TypeScript application. The diagram below shows how a request flows from a browser client all the way down to object storage and the database.

```text
Browser SPA / WebDAV / API clients / downloader agents
                    |
                    v
             Hono application
                    |
        middleware + route modules
                    |
                    v
                 usecases
                    |
             ports / Deps object
                    |
   +----------------+----------------+
   |                |                |
 repos          gateways         providers
   |                |                |
Drizzle DB    S3 / Cloud / mail   CF APIs / changelog
```

The primary deployment target is Cloudflare Workers. Node.js/Docker is the backup runtime, and the same Hono app is adapted for other serverless targets including AWS Lambda, Vercel, Netlify, and Azure Functions. Business logic does not fork by deployment target — platform-specific code is confined to `server/platform/` and the thin entry-point adapters.

### Request Layers

| Layer | Responsibility |
|---|---|
| **Hono route modules** (`server/http/`) | Path shape, request validation, response serialization, route-level auth guards, OpenAPI metadata |
| **Usecases** (`server/usecases/`) | Business workflows: file lifecycle, quota, sharing, teams, WebDAV, remote download, admin |
| **Ports** (`server/usecases/ports*.ts`) | Contracts usecases need from persistence and external services |
| **Adapters** (`server/adapters/`) | Repos (Drizzle/DB), gateways (S3, email, Cloud), providers (CF APIs) |

### Browser Upload Path

1. The frontend calls `POST /api/objects` through the Hono RPC wrapper.
2. The server creates a draft `matters` row plus an `object_upload_sessions` row and returns presigned upload instructions.
3. The browser uploads bytes directly to S3/R2 with a raw `fetch` to the presigned URL — the ZPan server never touches file bytes.
4. The frontend calls the completion endpoint; the server verifies, activates the file record, and updates quota and usage.

## Supported S3-Compatible Backends

ZPan works with any S3-compatible object storage provider. The following have been tested and are known to work:

| Provider | Notes |
|---|---|
| **Cloudflare R2** | Recommended for Workers deployments. No egress fees. |
| **AWS S3** | The reference S3 implementation. All regions supported. |
| **Backblaze B2** | Cost-effective option with S3-compatible API. |
| **MinIO** | Self-hosted S3-compatible storage for full on-premises control. |
| **RustFS** | Lightweight self-hosted S3-compatible storage; bundled option in the Docker Compose quickstart. |
| **Tigris** | Globally distributed object storage with an S3-compatible API. |

Any other service that implements the S3 protocol — including presigned `PUT` and `GET` operations — is compatible.

## Product Boundaries

ZPan is intentionally scoped. Understanding what it is and is not prevents surprises.

**ZPan is a good fit when you want:**

- A focused S3-backed web drive instead of a storage-provider zoo
- A self-hosted image bed and file-sharing app backed by your own bucket
- Cloudflare-native deployment without maintaining a VPS or NAS
- Browser-to-S3 transfers instead of app-server file proxying
- Tool integrations for screenshot apps, publishing workflows, WebDAV, remote download, and API-driven automation

**ZPan is not trying to be:**

- A real-time document co-editing suite like Nextcloud Office
- A general-purpose cloud-drive aggregator like AList
- A local server directory browser like File Browser
